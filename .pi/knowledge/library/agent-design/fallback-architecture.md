# 降级回答：Agent 在模型缺失、工具失败与证据不足时的诚实与可操作策略

## 摘要与问题边界

降级回答不是“回答得更差”，而是在 Agent 无法依赖完整模型、工具或证据时，仍然向用户交付诚实、可操作且边界清晰的信息。它的核心原则是不把推测包装成事实，也不把系统失败隐藏为“暂时无结果”。触发条件有三类：模型不可用或返回空、工具调用失败或超时、检索证据不足以支撑确定性结论。本设计把问题限制在“回答生成”环节，不覆盖恶意注入、UI 降级或网络传输层容灾；它也不允许 Agent 以推测冒充事实，或以免责声明包装不可验证的断言。

## 核心概念与数据模型

1. **回答置信度（AnswerConfidence）**：采用 `none`、`low`、`medium`、`high` 四级。`none` 表示没有任何本地或工具证据；`low` 表示仅有单条未交叉验证的来源；`medium` 表示两条以上来源一致但 freshness 超时；`high` 表示至少两条独立来源且 freshness 在阈值内。该分级由可替换的 `ConfidenceScorer` 接口计算，而不是模型直接输出，从而保证不同模型实现下评分一致。

2. **可用能力清单（CapabilityInventory）**：记录模型、工具、本地文件知识库、缓存和人工通道的实时健康状态。每个条目包含 `status`（`healthy`、`degraded`、`unavailable`）、`lastCheckedAt` 和 `failureReason`。能力清单在每次请求前被刷新，但不必在请求内部同步等待，避免探活失败拖慢响应。

3. **证据链（EvidenceChain）**：每个事实必须携带来源路径、检索时间、校验和与 freshness 时间戳。缺失任一字段即视为不可验证片段。证据链中的条目可以来自 `file`、`tool`、`cache` 或 `model`，并在最终答案中按段落编号引用。同一来源的多个片段合并为一条引用，避免冗余。

4. **降级策略图谱（FallbackPolicy）**：枚举 `static_cache`、`synthetic_summary`、`human_handoff`、`defer` 四种策略。`static_cache` 用于已知稳定的项目级事实；`synthetic_summary` 仅在存在部分证据时启用；`human_handoff` 用于 `none` 置信度且涉及安全或合规的问题；`defer` 用于请求用户补充信息，例如反问“请提供具体文件路径”。策略选择由 `PolicyRouter` 根据能力清单与证据链共同决定。

5. **用户承诺契约（ResponseCommitment）**：把输出拆分为“可验证事实”“基于规则的推断”“待确认假设”三部分，并在每部分前加明确前缀。例如“已知：”“推断：”“待确认：”。推断和假设部分必须同时给出置信度与证据编号，或明确说明无证据。若整段无证据，则整段必须标注为“无法验证”。

6. **可替换接口边界（ReplaceableBoundary）**：将 `ConfidenceScorer`、`PolicyRouter`、`AnswerFormatter` 定义为独立接口。会话编排层只依赖这些接口，具体实现可以随项目替换。边界内不得直接调用模型或文件系统，所有外部依赖通过能力清单注入。接口契约必须包含降级理由字段，以便审计和调试。

## 设计决策与取舍

### 诚实性优先于完整性

当证据不足时，优先告诉用户“我不能回答”，而不是给出看似完整但来源不明的答案。代价是可能增加用户操作成本，但可避免后续事实性错误的修复成本。例外：若用户明确要求“基于现有信息给出最佳猜测”，则启用 `synthetic_summary`，但输出必须标注为推断，且不包含具体数值或操作指令。

### 工具失败时的静默重试与立即降级

允许对幂等工具进行最多一次带抖动的重试；非幂等工具或超时超过阈值时直接降级。重试次数、退避策略和超时阈值作为策略配置项暴露，而不是写死在调用方。例外：涉及用户资产变动的工具不允许重试，必须立即降级并提示人工确认，防止重复操作导致状态变更。

### 证据不足时合成还是拒答

合成回答仅在满足两个条件时启用：存在至少一条相关证据，且系统明确声明输出为“基于不完整信息的推断”。否则执行拒答，并给出可执行的下一步，例如“请补充 `docs/budget.md`”或“切换人工处理”。该边界防止模型把“无答案”润色成“有答案”，也防止用户将推断误认为决策依据。

### 缓存与实时检索的边界

缓存仅用于回答已知稳定的项目级事实，例如 `pnpm` 版本、依赖路径。 freshness 超过配置阈值时，缓存内容自动降级为“过期引用”，不再作为 `high` 置信度证据。若缓存与实时检索冲突，以实时检索为准，并记录差异事件，用于后续审计阈值调整。

### 人工接管与自动降级的触发条件

当置信度为 `none` 且涉及用户资产、安全或合规问题时，直接触发 `human_handoff`。自动降级适用于 `low` 或 `medium` 且用户可二次确认的场景。该边界需要在配置中明确列出“高风险意图关键词”，而不是由模型自行判断，避免模型在不确定时逃避责任。关键词列表由产品和合规团队共同维护，而不是由运行时模型自行学习。

## 可执行的实施流程

1. 定义能力基线：列出所有可调用模型、工具、知识库与外部服务，并标注默认健康状态。基线写入 `packages/pi-agent` 的配置文件，随版本发布。

2. 为每条调用路径声明降级策略：在 `CapabilityInventory` 中映射每条模型或工具路径到 `FallbackPolicy`。例如，文件检索失败时默认使用 `static_cache`，而代码执行工具失败时默认 `human_handoff`。同一工具在不同意图下可映射到不同策略，因此策略表应支持意图级覆盖。

3. 实现健康探测：对模型、工具、文件系统做异步探活，将结果写入 `CapabilityInventory`。探测失败不阻断请求，而是影响后续策略路由。探测周期和超时阈值需可配置。

4. 实现证据评分：根据来源数量、交叉验证、来源类型和 freshness 计算 `AnswerConfidence`。评分逻辑单元测试覆盖所有四级状态，并针对本地文件、工具返回和模型生成分别设置权重。

5. 实现策略路由：根据置信度与能力状态选择策略，并记录决策理由。理由随答案一起返回，便于用户和审计追溯。路由规则应支持按意图标签覆盖。

6. 实现输出模板与免责声明：为每种策略准备模板，自动插入“证据不足”“来自缓存”等前缀。模板与业务文本分离，支持多语言。模板中预留证据引用占位符。

7. 实现可观测性埋点：在降级触发、策略选择、输出渲染时输出结构化日志。事件包含 `requestId`、`policy`、`confidence`、`evidenceCount`、`capabilityStatus`。日志保留周期不低于 30 天。所有指标应通过统一事件总线收集，避免在渲染层重复埋点。

8. 建立评审与版本化：每次策略调整需通过代码审查与 QA 样例回归，并写入 `CHANGELOG.md`。策略文件使用语义版本管理，旧版本保留至少两个发布周期，以便回滚。回滚时只需切换策略文件版本，无需修改会话编排代码。

## 代码示例：本地文件知识库的 TypeScript 降级解析器

    interface DegradedAnswerRequest {
      query: string;
      evidence: EvidenceChain[];
      capabilities: CapabilityInventory;
    }

    function resolveDegradedAnswer(req: DegradedAnswerRequest): DegradedAnswer {
      const confidence = scoreConfidence(req.evidence);
      const policy = routePolicy(confidence, req.capabilities);
      return formatAnswer(req.query, req.evidence, policy, confidence);
    }

输入为自然语言查询、证据链和能力清单；处理阶段先评分再路由；输出为包含 `confidence`、`policy`、`segments` 和 `nextAction` 的结构化答案，渲染层再将其转换为带引用的自然语言。`routePolicy` 会检查 `capabilities` 中是否存在可用模型，没有则直接选择 `static_cache` 或 `human_handoff`。

## 性能、质量与可观测性指标

- **降级率**：降级回答数除以总会话数，按策略维度拆分。测量方式：在答案输出事件中记录 `policy !== 'full'`。
- **证据覆盖率**：有引用来源的句子占总输出句子的比例。测量方式：在 `AnswerFormatter` 中给每句打标签，统计有 `evidenceRef` 的句数。
- **用户接受率**：用户点击“确认有用”或继续执行推荐动作的会话比例。测量方式：在会话闭环中收集显式反馈与隐式动作。
- **端到端延迟**：从收到请求到返回答案的 p95 延迟，按策略和健康状态分组。测量方式：在请求入口和出口打点。
- **人工升级率**：触发 `human_handoff` 的会话占比。测量方式：统计 `policy === 'human_handoff'` 的事件。
- **缓存误用率**：以过期缓存作为 `high` 置信度证据的回答数。测量方式： freshness 审计任务扫描输出中的引用，并与缓存记录对比。

## 失败模式、诊断证据与恢复动作

- **模型超时或不可用**：诊断证据为健康探测失败或模型响应为空；恢复为切换到 `static_cache` 或 `human_handoff`，并向用户声明“模型不可用，当前回答来自缓存”。
- **工具返回异常或空结果**：诊断证据为错误码或返回体为空；恢复为使用部分证据、置信度降级为 `low`，并提示用户补充信息或重试。
- **证据冲突**：诊断证据为两条来源给出相反结论；恢复为并列呈现冲突，不自行合成，置信度取 `low`，并建议用户人工核对。
- **缓存陈旧导致事实偏差**：诊断证据为 freshness 超过阈值；恢复为标记为过期、触发重新检索或降级为 `low`，并记录审计事件。
- **策略误判**：诊断证据为大量 `medium` 置信度问题被错误降级；恢复为调整阈值、A/B 测试并回归 QA 样例。
- **用户忽略降级提示**：诊断证据为用户在 `low` 置信度答案基础上继续执行高风险操作；恢复为在关键操作前增加二次确认，并将该交互记录为训练样本。

## 问答测试样例

1. **正向**：问“当前项目使用 pnpm 哪个版本？”系统从 `package.json` 的 `packageManager` 字段读取答案，给出带引用的高置信度回答。
2. **正向**：问“API 如何创建 AgentSession？”系统根据 `packages/pi-agent` 源码和 `AGENTS.md` 给出实现步骤，并标注来源。
3. **边界**：问“项目预算是否超支？”本地知识库无 `budget.md`，系统返回“未找到预算文件，无法判断”，并建议补充文件或转人工。
4. **边界**：问“比较 pi-coding-agent 0.83 与 0.90 的 API 差异。”本地只有 0.83 文档，系统回答 0.83 的已知行为，并声明 0.90 版本无本地证据，不推断未发布差异。
5. **边界**：问“`pnpm-lock.yaml` 是否被忽略？”系统发现 `.gitignore` 中未包含该文件，但 `AGENTS.md` 要求保留，于是给出“未被忽略，且应保持同步”的带引用回答，置信度为 `medium`。
6. **无证据拒答**：问“这家公司明年股价是多少？”系统没有外部市场数据，返回“无证据，无法预测”，并拒绝任何数字性回答。
7. **无证据拒答**：问“pi SDK 的未发布功能有哪些？”系统没有未来版本信息，返回“不能访问未发布内容”，建议查看官方仓库或等待发布说明。

## 维护、版本、来源与相邻主题

降级策略应随代码版本化，存储于 `packages/pi-agent` 的配置与 `.pi/knowledge` 中。变更需记录来源、阈值调整理由、相关失败模式和 QA 样例结果。版本发布前必须执行全量 QA 样例回归，并更新 `CHANGELOG.md`。策略来源包括源码提交哈希、相关 ADR 编号和实验记录，以保证可审计。相邻主题包括：工具编排、检索增强生成、人在回路、可观测性、模型选择。降级回答与这些主题共享证据链和置信度模型，但专注于“无法继续时的输出策略”。它不应替代工具重试、权限校验或输入验证，而是位于这些层之后的最终回答保护层。

## 结论

事实：当模型、工具或证据不可用时，Agent 必须显式降级而非伪造答案，且所有输出都应可被追溯到能力清单或证据链。推论：将置信度、策略和格式化拆分为可替换接口，能够提升系统的长期可维护性和跨项目复用性。未知：不同领域用户对“可接受降级”的容忍阈值、人工升级的真实成本、以及合成推断在业务场景中的误用风险，仍需通过实际运行数据进一步验证。
