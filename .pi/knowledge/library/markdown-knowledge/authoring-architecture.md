# Markdown 文章编写的架构化方法：读者、边界与可检索正文的组织

## 摘要与问题边界

知识库文章失效通常不是因为缺少信息，而是信息未被组织成检索器和 Agent 可引用的单元。本文讨论 Markdown 知识写作的编写阶段，目标是在落笔前先建立读者、问题边界与事实来源的契约，再据此组织正文。覆盖范围包括单篇文章的元数据设计、标题层级、事实分层、来源标注与可替换接口；不覆盖实时协作、权限控制、多媒体嵌入、渲染管线与存储后端选型。目标读者是负责知识库长期演进与边界管理的设计者。

## 核心概念与数据模型

1. 读者画像：每篇文章必须声明目标读者的角色、决策半径与技术前提。未声明读者的文章不得进入评审。
2. 问题边界：用“本文覆盖”与“本文不覆盖”明确范围。边界不是免责声明，而是接口契约。
3. 事实来源：将陈述分为项目可验证、外部引用、推论、未知四类，并用统一标签标记。
4. 检索单元：以 H1 为根主题、H2 为子主题、段落或列表项为原子块，每个原子块应独立回答一个具体问题。
5. 可替换接口：内容模型与渲染器解耦。内容模型定义标题、段落、来源、标签；渲染器只负责呈现，不决定语义。
6. 版本锚点：每篇文章携带文件路径、最近审阅日期与对应代码或文档的提交哈希，用于判断信息是否过期。

## 设计决策与取舍

### 读者与边界的优先级

两者并行起草，但读者画像优先。边界约束“不写什么”，读者画像决定“写到什么深度”。冲突时以读者决策半径为准。

### 事实分层策略

所有事实必须显式分层，禁止隐含权威。项目可验证事实应指向文件路径与行号；外部引用给出 URL 与访问日期；推论标注“由…推断”；未知标注“未验证”。混写会污染检索结果。

### 篇幅控制原则

一个 H1 对应一个主题，正文控制在两千到三千中文字符。内容跨越多个边界时必须拆分为多篇并建立跨引用，而非扩张单篇边界。

### 目录与标签的分工

目录树表达主题域与主题的包含关系，标签表达视角与重点。路径决定物理归属，标签决定检索面。禁止用标签替代目录，也禁止目录承担交叉检索职责。

### 人工与工具的边界

人类负责边界划定、来源核实与最终断言；工具负责补全句式、检查层级一致性与标记缺失来源。工具生成段落必须经人工确认来源标签后方可提交。

## 可执行的实施流程

1. 在文章顶部写入读者画像与决策半径。
2. 撰写摘要与问题边界，列出覆盖与不覆盖范围。
3. 枚举计划写入的事实并预先分配来源标签。
4. 设计标题层级：一个 H1，三到五个 H2，每个 H2 下不超过三个 H3。
5. 按检索单元撰写正文，每个段落或列表项聚焦一个判断。
6. 在关键断言后插入来源标注：文件路径、提交哈希或显式“未验证”。
7. 执行可检索性检查：用五个预期问题检索文章，确认每个问题都能在标题或原子块中找到答案。
8. 提交到版本控制，并在文章末尾更新文件路径、审阅日期与提交哈希。

## 性能、质量和可观测性指标

1. 检索召回率：对预设问题集执行检索，命中相关块的问题数除以总问题数，目标不低于百分之九十。
2. 来源标注覆盖率：已标注来源的断言数除以总断言数，项目可验证事实须达百分之百。
3. 边界违规率：评审中发现的越界内容条数除以文章总条数，目标低于百分之五。
4. 版本新鲜度：当前日期与最近审阅日期的差值，超过九十天触发复审。
5. Agent 引用准确率：Agent 回答中引用的块确实包含答案的比例，通过人工抽检测量。

## 失败模式

1. 读者画像漂移：文章中途更换目标读者，导致深度不一致。证据是同一篇中同时出现实现细节与高层决策建议。恢复动作是拆分或重写摘要。
2. 边界蔓延：正文写入不覆盖范围。证据是“本文不覆盖”中的关键词在正文中被解释。恢复动作是删除越界段落并建立跨引用。
3. 来源不可验证：标注为项目可验证的断言无法定位到文件或行号。证据是检索路径不存在。恢复动作是降级为“未验证”或补充来源。
4. 标题层级断裂：出现 H3 直接挂在 H1 下或缺少 H2。证据是标题层级不连续。恢复动作是插入 H2 或合并层级。
5. 版本锚点丢失：文章缺少审阅日期或提交哈希。证据是元数据字段为空。恢复动作是阻止合并并要求补全。

## 问答测试样例

1. 正向：本方法要求文章先定义什么？答案：读者、问题边界和事实来源。
2. 正向：一个检索单元应满足什么条件？答案：能独立回答一个具体问题。
3. 边界：本文是否覆盖实时协作？答案：不覆盖，属于摘要列出的不覆盖范围。
4. 边界：文章超过三千中文字符时应如何处理？答案：拆分为多篇并建立跨引用，不扩张边界。
5. 无证据：Markdown 渲染器是否应决定内容模型？拒答条件：未提供渲染器选型证据，答案只能是渲染器只负责呈现、不决定语义。
6. 无证据：哪种存储后端最适合本地文件知识库？拒答条件：本文不覆盖存储后端选型，必须拒绝回答。

## 维护、版本、来源与相邻主题

维护与代码审阅同步：每次迭代后检查版本锚点，每季度全面审阅。内容模式变更使用语义化版本，标题结构变化为次要版本，纯文本勘误为补丁版本。来源优先使用项目级可验证材料：AGENTS.md、.pi/knowledge 中的相邻文章、代码文件与官方 SDK 文档。相邻主题关系：Skills 是可复用执行模板，Prompts 是交互上下文，ADR 记录不可逆决策，本文聚焦单篇文章编写契约。运行时信任是安全边界，不是内容来源。

## 结论

事实：文章必须先声明读者、边界和来源；检索单元由标题层级决定；版本锚点必须存在。推论：按此架构组织的知识库能显著提升 Agent 引用准确率与长期可维护性。未知：在多媒体、多语言混合、大规模自动化生成等场景下，该内容模型是否保持同等效果，尚需项目级实验验证。
