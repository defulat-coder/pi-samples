# 标题层级：验证与运维视角

Markdown 标题层级：在 H1 到 H3 中建立稳定可观测的知识结构

摘要与问题边界

Markdown 标题层级不是单纯的排版样式，而是本地文件知识库的结构化信号。本文只讨论 H1 到 H3 在 `.pi/knowledge`、`docs/` 等本地 Markdown 知识库中的用法，不覆盖 H4 及以下的细粒度样式、YAML frontmatter 元数据，也不规定具体文档的写作内容。视角定位为验证与运维：把标题层级当作可观测对象，记录解析成功、失败、延迟、容量和恢复证据，避免只看一次成功请求就得出结构健康的结论。

核心概念与数据模型

1. 文档节点：每篇 Markdown 文件解析后生成一个 AST 文档节点，H1 作为唯一根标题。若同一文件出现多个 H1，即视为结构异常。
2. 章节节点：H2 对应一个章节节点，包含标题、锚点 ID、正文分块范围，用于摘要召回和导航。
3. 小节节点：H3 作为最小操作单元，承载具体故障域、检查项或配置步骤，每个 H3 独立可寻址。
4. 层级栈：解析器维护当前层级栈。遇到 H1 清空栈；遇到 H2 压入新章节；遇到 H3 在章节下追加小节。
5. 摘要索引：由 H1 和 H2 组成索引表，被检索器用于召回候选文档；H3 用于精确定位答案。
6. 导航边：同一层级节点之间的前驱与后继关系，支持快速跳转到相邻故障域或上下章节。

设计决策与取舍

为什么只保留 H1 到 H3

H1 到 H3 已足够覆盖摘要、分块和导航。引入 H4 会放大解析歧义，导致分块过细、检索噪音增加。如果单篇文档确实需要 H4，应视为内容过密，优先拆分为多篇文档。

单一 H1 还是多个 H1

强制每篇文档只有一个 H1，可降低根节点歧义。历史文档迁移时可能需要修复，但好处是检索召回时不会把同一文件内的多个主题混淆。

自动生成锚点还是手写锚点

自动生成锚点 slug 可保证稳定性与一致性；手写锚点利于可读性，但容易拼写错误。建议由解析器生成 slug，并以标题文本作为校验依据。

顺序式层级还是允许跳级

禁止跳级。H3 必须出现在 H2 下。允许跳级会导致层级栈失衡，解析器难以恢复，也会破坏导航边的连续性。

摘要是否包含 H3

默认摘要只取 H1 和 H2，避免 H3 噪音。当查询明显需要 H3 级细节时，可启用扩展摘要模式，但需单独监控其召回准确率。

可执行的实施流程

1. 扫描仓库，列出所有 `.md` 文件和 `.pi/knowledge` 目录下的知识文件。
2. 运行标题解析器，收集每篇文章的 H1 到 H3 列表及其行号。
3. 对每篇文章验证：H1 数量等于 1，H2 数量大于等于 1，H3 必须在 H2 下出现。
4. 生成锚点 slug：将标题转为 kebab-case，并校验 ASCII 范围和长度限制。
5. 构建摘要索引：每个 H2 生成一段 60 到 120 字的摘要，记录其 H1 父级和文件路径。
6. 将索引写入本地 JSON 或 SQLite 缓存，记录生成时间戳和版本哈希。
7. 在 Web 或 Agent 接口中暴露导航边：上一节、下一节、同文件 H2 列表。
8. 建立周期性校验任务：比较文件 mtime 与缓存时间戳，若文件更新则重新解析并告警。
9. 在故障恢复时优先从缓存索引重建导航，而非重新读取全部文件。
10. 记录每次解析耗时、错误数和缓存命中率到结构化日志。

本地文件知识库示例：输入、处理与输出

输入示例：

处理逻辑：解析器逐行识别 `#` 标记，维护层级栈，遇到 H1 清空栈，遇到 H2 创建章节节点，遇到 H3 在章节下追加小节节点，并生成锚点 slug。

性能、质量和可观测性指标

1. 解析延迟：单个文件解析 p99 小于 50 毫秒，使用 high-resolution timer 从读取文件到输出 AST 测量。
2. 缓存命中率：索引缓存命中应大于等于 95%，计算命中次数除以总请求次数。
3. 结构错误率：异常 H1 数量、跳级、空标题比例应小于 0.5%，通过周期性校验任务计数。
4. 摘要覆盖率：H2 有摘要的比例为 100%；启用扩展摘要时，H3 覆盖率应大于等于 90%。
5. 导航可用性：Web 页面加载后 1 秒内出现导航边，通过前端性能指标和端到端测试断言。
6. 恢复时间：索引缓存失效后，全量重新生成索引应小于 30 秒，在灾难恢复演练中测量。

失败模式、诊断证据与恢复动作

1. 重复 H1：诊断证据为解析器发现 H1 数量大于 1，错误码 E101，日志记录文件路径与行号。恢复动作为标记文档需修复，降级使用第一个 H1，并触发告警。
2. 标题跳级：H3 出现在 H1 之后没有 H2。诊断证据为层级栈深度异常，日志记录前序节点层级。恢复动作为降级为 H2 或忽略该 H3，防止导航栈失衡。
3. 锚点冲突：两个 H2 生成相同 slug。诊断证据为 slug 去重计数器大于 0。恢复动作为自动追加数字后缀，并记录告警。
4. 缓存陈旧：文件 mtime 大于缓存时间戳。诊断证据为校验任务返回 drift 列表。恢复动作为重新解析并更新缓存，若失败则返回 503 并提示维护。
5. 解析器崩溃：非法字节或极长标题导致异常。诊断证据为进程退出码非零、堆栈跟踪。恢复动作为捕获异常、隔离文件、使用上一版本缓存，并记录恢复事件。
