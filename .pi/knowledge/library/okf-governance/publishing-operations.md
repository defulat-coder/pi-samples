# OKF 知识治理中的发布流程：验证与运维视角

## 摘要与问题边界

发布流程解决的是：作者在本地的草稿如何经过验证、索引编译与线上切换，最终成为可被检索器与 Agent 引用的稳定知识视图。本文的观察边界限定在“本地文件型知识库”（Markdown、TypeScript 类型定义、Web 构建产物）的发布链路，涵盖从作者提交到线上可见的全过程；不包含语义审核、人工审批、权限治理与实时协同编辑。核心关注点是性能、稳定性、容量与故障恢复，所有结论都需要有可验证的运行证据，而不是单次成功请求的主观推断。

## 核心概念与数据模型

1. **作者草稿（Author Draft）**：作者在工作区中编辑的原始文件集合，允许不一致、临时链接和未完成的片段。草稿阶段只保证可写，不保证可读性。
2. **快照包（Snapshot Bundle）**：草稿达到“待发布”状态后，系统将其打包为不可变快照，包含文件内容、校验和、作者签名与时间戳。后续所有操作都基于快照，而非直接读取工作区。
3. **验证报告（Validation Report）**：对快照执行的格式校验、链接可达性检查、Schema 校验、构建测试与最小健康检查的结果集合。报告必须明确区分“阻塞性错误”与“警告”。
4. **索引编译产物（Index Artifact）**：由验证通过的快照生成的检索结构，包括倒排索引、术语映射、向量嵌入与片段边界表。索引产物需要与快照版本绑定。
5. **发布候选（Release Candidate）**：附带版本号、来源快照标识、验证报告与索引产物的可发布单元。只有发布候选才有资格进入线上切换。
6. **服务视图（Serving View）**：线上读者与 Agent 实际查询到的知识视图，通过路由槽（Routing Slot）指向当前生效的发布候选。同一时间只允许一个生效槽，切换必须是原子的。

## 设计决策与取舍

### 快照不可变优于原地覆盖
采用不可变快照后，回滚只需切换路由槽，无需重新生成内容。代价是磁盘占用增加，因此必须设置保留策略与去重机制。

### 异步验证优于同步阻塞
验证阶段可能调用外部构建、链接检查与嵌入模型，耗时从秒级到分钟级不等。异步执行可避免阻塞作者界面，但要求发布系统具备任务队列、超时与重试能力。

### 增量索引与全量重建混合
对于小改动使用增量索引可将编译时间控制在秒级；当 Schema 变更、术语表重排或检测到索引损坏时，强制全量重建。增量路径需要维护基线版本映射，失败时自动退回到全量。

### 原子切换与双槽保留
线上服务维护“当前槽”与“候选槽”。切换时先完成候选槽的预热，再原子修改路由指针。切换失败可在毫秒级回切到旧槽，但双槽保留会 doubling 内存与磁盘峰值。

### 失败隔离：阶段内重试，阶段间不可跳过
每个阶段内部允许有限重试；一旦某阶段失败，必须回到作者草稿或重新触发快照，而不能跳过验证直接上线。该策略降低了故障面，但对作者体验有轻微影响。

## 可执行的实施流程

1. 作者在本地工作区完成草稿编辑，并通过最小自检查（lint、本地构建）。
2. 作者标记“请求发布”，系统立即锁定草稿并生成不可变快照包。
3. 系统将快照写入临时存储，计算 SHA-256 校验和，并记录作者、时间与父版本。
4. 触发验证流水线：格式校验、内部链接检查、TypeScript 类型检查、Schema 校验、关键断言测试。
5. 若验证通过，进入索引编译：生成倒排索引、术语映射、向量嵌入与 Web 构建产物；若失败，生成报告并终止。
6. 验证与索引产物合并为发布候选，写入候选槽，并执行预热查询。
7. 执行原子切换：更新路由指针指向候选槽，旧槽保留为回滚基线。
8. 切换后运行健康检查：采样查询延迟、错误率、索引完整性，观察窗口结束且无异常后标记发布完成。

## YAML 示例：本地文件知识库的发布流水线

```yaml
pipeline:
  input:
    workspace: ./knowledge/drafts
    trigger: manual
    base_snapshot: snap-20250815-001
  stages:
    snapshot:
      output: ./staging/snap-{timestamp}.tar.gz
      checksum: sha256
    validate:
      checks: [markdown-lint, link-check, typecheck, schema]
      timeout: 120s
      retries: 2
    index:
      incremental: true
      base: snap-20250815-001
      outputs:
        inverted: ./index/inverted.json
        embeddings: ./index/embeddings.bin
        term_map: ./index/terms.json
    release:
      candidate_id: rc-{snapshot}-{timestamp}
    switch:
      strategy: atomic-blue-green
      health_window: 60s
      rollback_on_error: true
```

输入是作者工作区的草稿与父快照标识；处理阶段分别完成打包、验证、索引编译与候选生成；输出是带版本标识的服务视图与回滚基线。

## 性能、质量与可观测性指标

1. **端到端发布延迟**：从作者触发到健康检查通过的时间。测量方式为流水线各阶段时间戳差值，目标 p99 应低于 5 分钟。
2. **验证失败率**：每百次发布中验证阶段失败的次数，按错误类型分组。测量来源是验证报告元数据。
3. **索引编译耗时与增量命中率**：记录每次编译是全量还是增量，以及耗时。测量方式是在索引产物中写入 `build_mode` 与 `duration_ms`。
4. **切换成功率与回滚时间**：统计原子切换成功次数与自动回滚次数；回滚时间指路由指针回到旧槽的时间差。
5. **发布后查询延迟与错误率**：切换后 10 分钟内采样检索 API 的 p50、p99 延迟与 5xx 比例，作为上线质量门。
6. **容量占用**：快照、索引与双槽同时存在的磁盘与内存峰值，测量方式是发布高峰期的资源快照。

## 失败模式、诊断证据与恢复动作

1. **验证阶段偶发失败**：证据为同一快照重试后通过，且错误集中在网络依赖或外部服务。恢复动作是重试验证任务，若连续失败则检查依赖可用性。
2. **索引编译内存不足或超时**：证据为编译进程退出码 137 或超过阈值日志。恢复动作是降低并发、改用全量重建或扩容编译节点。
3. **快照校验和不匹配**：证据为快照读取时 SHA-256 与元数据不一致。恢复动作是拒绝该快照，要求作者重新触发发布。
4. **切换后部分读者看到旧内容**：证据为路由指针已更新但 CDN、浏览器缓存或副本未刷新。恢复动作是检查缓存 TTL、强制失效或等待自然过期，必要时回滚。
5. **发布后查询错误率上升**：证据为健康窗口内 5xx 或异常延迟超过阈值。恢复动作是立即原子回切到旧槽，保留候选槽用于复现，并通知作者修复。

## 问答测试样例

1. **正向问题**：如何发布一篇新草稿？应回答从自检查、快照、验证、索引到切换的完整 8 步流程。
2. **边界问题**：如果只有术语表顺序调整，是否可以跳过索引编译？答：不一定；若顺序影响片段边界或嵌入映射，则仍需编译；系统应根据变更文件集合与索引元数据的差异判断。
3. **边界问题**：验证报告全是警告是否可以上线？答：取决于策略配置；默认策略下警告不阻塞，但应在报告中记录并建议修复。
4. **无证据拒答**：这次发布需要多长时间？答：不能仅凭单次成功请求给出保证，应引用最近 7 天同类快照的 p50/p99 数据。
5. **无证据拒答**：为什么线上结果与本地不一致？答：需要检查路由指针版本、缓存状态与读取副本同步证据，不能仅凭猜测推断。
6. **诊断问题**：切换后 30 秒出现错误峰值，系统做了什么？答：若策略启用自动回滚且健康窗口未关闭，应查看审计日志确认是否触发回切，并保留候选快照用于复现。

## 维护、版本、来源与相邻主题关系

快照、发布候选与服务视图都需要版本标识，推荐采用 `snap-{date}-{seq}`、`rc-{snap}-{timestamp}` 与 `view-{rc}` 三级命名。保留策略建议：草稿保留 7 天，快照保留 30 天或最近 20 个，发布候选在切换成功后保留 14 天。索引产物应与快照同名存储，便于审计。来源信息需记录作者、触发方式、父版本与依赖的构建工具版本。发布流程与“内容建模”“权限治理”“检索排序”相邻：内容建模决定 Schema 与索引结构；权限治理决定谁能触发发布；检索排序消费发布后的索引产物，但不参与发布决策。

## 结论

**事实**：发布流程由草稿、快照、验证、索引编译、发布候选与线上切换六个阶段组成；每个阶段都产生不可变产物；切换使用原子路由槽并保留回滚基线。

**推论**：在本地文件型知识库中，异步验证与增量索引能够将常见发布延迟控制在分钟级；不可变快照与双槽设计使回滚时间主要受限于健康窗口长度与路由传播速度。

**未知**：特定外部依赖的可用性波动对验证失败率的具体贡献比例、长文档在嵌入模型上的内存峰值曲线、以及不同缓存层对切换后一致性延迟的实际分布，都需要在真实运行环境中通过持续观测获得证据，而不能由单次成功发布推导得出。
