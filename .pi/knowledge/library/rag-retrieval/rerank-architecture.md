# 重排序：在候选集收缩阶段提升相关性并控制模型延迟

## 摘要与问题边界

在检索增强生成（RAG）管线中，重排序（Rerank）是连接召回层与生成层的可选第二阶段。它的职责不是扩大召回，而是对第一阶段返回的有限候选集进行更精细的相关性排序，从而把最相关的片段推到生成器能够消费的顶部位置。重排序器必须运行在延迟预算之内，并且可以被替换为不同模型或策略，而不影响上游检索器与下游生成器的契约。

责任边界如下：
- 上游检索器：保证在足够大的候选池中召回相关文档，输出候选集、原始分数和来源标识。
- 重排序器：只接收固定大小或上限的候选集，输出新的排序与置信度。
- 下游生成器：按最终 top-K 消费，不依赖重排序器的内部模型。
- 调度/编排层：负责超时、降级、缓存、模型路由与可观测性。

## 核心概念与数据模型

1. 查询对象：包含原始查询文本、改写后的查询、意图标签、时间约束和租户标识。重排序器使用原始查询与改写查询进行双编码或交叉编码。
2. 候选单元：每个候选包含文档标识、块索引、文本内容、第一阶段的得分、检索来源（向量、关键词、混合）以及元数据（如文件名、更新时间、权限）。
3. 候选集契约：输入给重排序器的列表必须满足 `0 ≤ N ≤ N_max`，其中 `N_max` 由模型上下文长度与延迟预算共同决定。顺序对重排序器是建议，不是约束。
4. 重排序器接口：声明 `rerank(query, candidates, options) -> {results, scores, latency, modelId}`，其中 `options` 可包含超时、是否返回全部候选、是否启用缓存。
5. 分数语义：输出分数应统一为 `[0, 1]` 的校准概率，或保留原始 logit 并附带校准参数。禁止将不同模型的输出分数直接混用而不经过校准。
6. 结果与溯源：最终列表必须保留每个候选的原始来源、原始排名、重排后排名和重排置信度，以便审计、调试和 fallback。

## 设计决策与取舍

### 1. 两阶段解耦 vs 端到端联合训练
保持召回与重排独立。第一阶段的 embedding 或索引不能因重排序器升级而重训；重排序器可以在线替换。端侧联合训练会提高上限，但破坏可替换接口和可调试性。

### 2. 交叉编码器 vs 双编码器点分 vs 列表式重排
交叉编码器把查询与文档拼接输入，精度最高但延迟与候选数成正比。双编码器点分模型复用已有向量，延迟低但提升有限。列表式 LLM 重排利用长上下文一次比较多个候选，效果接近人工标注，但输出不稳定、解析成本高。选型时先固定候选数 N=20，测量 P95 延迟，再决定。

### 3. 候选集大小 N 的边界
N 不是越大越好。经验上，当第一阶段召回质量较高时 N 取 10–50 即可覆盖大部分相关文档；继续增加到 100 以上，NDCG 提升通常低于 2%，而延迟可能翻倍。N 必须写入接口契约，并让编排层能够按模型动态裁剪。

### 4. 何时触发与旁路
对简单事实查询、缓存命中、模型不可用或超时风险高的请求，应直接走旁路。旁路条件包括：候选集平均初筛分数低于阈值、查询字符数过短、模型队列长度超过阈值。旁路不是失败，而是 SLA 控制。

### 5. 分数融合与截断策略
重排序分数不应完全替代初筛分数。推荐线性融合：`final_score = α * rerank_score + (1-α) * normalized_initial_score`。α 在 0.7–0.9 之间按领域离线评估选择。对于重排置信度低于 0.5 的候选，应保留但标记为低置信，避免过度截断。

## 可执行的实施流程

1. 定义替换接口 `IReranker`，明确输入 schema、输出 schema、超时和降级语义。
2. 在初始检索器不变的前提下，输出候选集时附带 `initialRank`、`initialScore` 和 `retrieverId`。
3. 选择基线实现：先用双编码器余弦相似度或轻量交叉编码器建立可重复基线。
4. 在离线评估集上测量基线的 NDCG@5、NDCG@10、P95 延迟和与人工标注的 Kendall τ。
5. 实现候选集过滤：按 `N_max` 截断，按初筛分数阈值或去重策略预清理。
6. 在编排层实现超时、旁路和缓存：超时后返回未重排的候选集，并记录 `fallback=true`。
7. 实现分数归一化与融合模块，对多来源候选统一量纲。
8. 建立在线 A/B 框架：对比重排开启与旁路，监控质量指标、延迟、错误率和成本，设定回滚阈值。

## 配置与代码示例

```json
{
  "rerank": {
    "enabled": true,
    "retriever": "hybrid-search",
    "adapter": "cross-encoder-local",
    "candidateLimit": 24,
    "timeoutMs": 320,
    "fallbackStrategy": "initial-order",
    "scoreFusion": {
      "alpha": 0.8,
      "normalize": "min-max"
    },
    "observability": {
      "logLevel": "debug",
      "metrics": ["latency", "ndcg", "inversions"]
    }
  }
}
```

输入：第一阶段返回的 24 个候选，每个候选包含文本、来源、初筛分数。处理：本地交叉编码器把查询与每个候选拼接成 `[CLS] 查询 [SEP] 候选 [SEP]`，输出相关性概率；超时则触发 fallback，返回初始顺序。输出：按融合分数排序后的 top-10 列表，以及原始排名、重排分数、置信度标签。

## 性能、质量与可观测性指标

1. 端到端 P95/P99 延迟：从请求进入重排阶段到返回结果的时间。应在目标 SLA 以内，如 P95 ≤ 300 ms。
2. 重排器独占延迟：扣除网络与序列化，仅模型推理时间。用于判断模型是否满足预算。
3. NDCG@5 / NDCG@10：在标注集上测量重排后结果相对于理想排序的增益。必须同时报告召回阶段 NDCG 以分离责任。
4. 配对倒置率（Inversion Rate）：比较重排后顺序与人工标注的成对顺序差异。公式为 `(错误配对数)/(所有相关/不相关配对数)`。
5. Fallback 率与错误率：记录超时、模型异常、候选集不满足条件而旁路的比例。Fallback 率长期高于 10% 说明模型或容量不足。
6. 每请求 token 与成本：对按 token 计费模型，统计平均候选 token 数与总成本，用于容量规划。

## 失败模式、诊断证据与恢复动作

1. 模型超时导致全量旁路：证据为 P95 延迟接近或等于超时阈值，日志中 `fallback=true` 与 `reason=timeout` 激增。恢复：降低 N、使用更轻量模型、增加超时、对热点查询加缓存。
2. 分数漂移导致质量下降：证据为 NDCG@5 连续下降而召回层 NDCG 稳定。恢复：重新校准输出分数、回滚模型版本、检查训练/评估数据分布。
3. 候选集过小使重排无效：证据为 `N ≤ 2` 或倒置率为 0 但答案仍错。恢复：增大上游候选数、对低置信查询改写后二次检索，或在该路径下禁用重排。
4. 长文档截断造成信息丢失：证据为平均截断 token 比率高、相关段落位于截断点之后。恢复：强制 chunking 上限、采用滑动窗口或摘要生成器，将长文档压缩到模型上下文。
5. 重复与近似文档堆叠：证据为 top-K 中多个候选内容相似、来源相同，导致生成冗余。恢复：引入去重阈值（如 MinHash/Jaccard）、多样性重排或来源聚类。

## 问答测试样例

1. 正向：为什么重排序不用于扩大召回？
   答：重排序器的输入是有限候选集，它只能重排已知候选，不能发现新的相关文档。扩大召回是检索器和查询改写的责任。

2. 正向：如何为本地文件知识库选择候选集上限？
   答：由模型上下文长度、单文档平均 token 数和延迟预算共同决定。建议从 N=24 开始，按 P95 延迟与 NDCG 曲线收敛点调整。

3. 边界：候选集只有 1 个文档时是否应调用重排？
   答：不应调用。没有比较对象，重排只能返回原顺序，增加无谓延迟。应通过旁路规则直接返回。

4. 边界：重排后分数与初筛分数冲突怎么办？
   答：采用校准后的融合分数，并保留两者用于审计。如果冲突集中在低置信区，应标记而非直接截断。

5. 无证据：重排序模型是否总是比向量检索更准？
   答：不是。在候选集质量差、查询罕见或模型未覆盖的领域，重排可能引入偏差。是否更准需通过离线评估和在线 A/B 验证，而非先验断言。

6. 无证据：本地文件知识库能否使用在线 LLM 进行重排而不泄露内容？
   答：不能默认保证。若文档含敏感信息，应使用本地部署模型或经脱敏处理的代理，否则需拒答该部署方案。

## 维护、版本、来源与相邻主题关系

- 版本控制：重排序模型、接口 schema、分数融合参数应独立版本化。模型版本变更后，先在影子流量中对比 24 小时，再切换主流量。
- 来源管理：候选的来源字段必须稳定，便于追踪质量回归至具体检索器（向量、关键词、图谱）。
- 与嵌入检索的关系：重排是后者的精化阶段，不替代索引和 embedding。当 embedding 退化时，重排无法弥补。
- 与查询改写的关系：改写扩大语义空间，重排压缩排序误差；两者可串联，但应独立评估。
- 与混合搜索的关系：混合搜索决定候选来源与初筛分数，重排负责跨来源统一校准。两者边界在于分数是否已统一。
- 与评估/对齐的关系：重排的离线数据集应使用最终生成质量反馈校准，避免仅优化排序指标而忽略生成可用性。

## 结论

- 事实：重排序在 RAG 管线中是可选的第二阶段，只能对有限候选集重新排序，不能扩大召回。
- 推论：在候选集较小且第一阶段召回已覆盖相关文档时，轻量交叉编码器或点分模型可在可控延迟内显著提升 top-K 相关性；候选集过小、模型超时或文档截断会抵消收益。
- 未知：在特定领域（如法律、医疗）中，多语言长文档、表格与多模态片段的最优重排策略、校准方法与列表式模型的稳定性边界仍需通过项目级实验与人工评估确定。
