# HITL 工具审批：引入 pi-permission-system + 文件队列审批桥

Pi Workbench 的收件箱需要对齐 Fleet 的 Human-in-the-loop 语义：工具调用命中 `ask` 策略时 agent 挂起，审批请求进入收件箱，用户在 Web 端批准/拒绝后运行恢复。实现不自建策略引擎，而是引入 npm 扩展 `pi-permission-system`（allow/deny/ask + 通配符策略，`.pi/agent/pi-permissions.jsonc`），通过两处适配接入无 TUI 的 SDK 宿主：pnpm `patchedDependencies` 修其与 pi-ai 0.84 不兼容的 `getApiProvider` 导入，构建期 esbuild 预编译其 TS 源码为单文件 `.mjs` 后经 `extensionFactories` 注册。headless 环境下它的 ask 自动转文件队列（`PI_IS_SUBAGENT=1` 触发 subagent 转发路径），`ApprovalBridge` 监听 `.pi/permission-forwarding/` 的请求文件、落库 SQLite（`approvals` 表）、经 `/api/v1/approvals` 端点接收 Web 决策并原子回写响应文件（nonce 校验），审批挂起上限 10 分钟、超时落 `expired`。工具白名单（`read`/`grep`/`find`/`ls`/`bash`）由宿主在 `packages/pi-agent` 固定，Agent 文件永远不得声明或扩展工具；策略可以调整 allow/deny/ask，但不能扩大白名单。决策记录与状态是通用工作台数据进 SQLite，会话本体仍只存 Pi JSONL。
